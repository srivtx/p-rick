Software the world is missing, specified before anyone builds it.

p-rick hunts for genuine gaps in the software landscape — categories with no incumbents, problems with large audiences, theories nobody has written down — and does the research to specify them: gap verification against everything that exists, formal models, architectures, evaluation designs, and honest confrontation with the reasons each gap has survived. Every paper ships with a PDF and a plain-language essay. Research first; products later.

Papers

Two arcs. Series I specifies user-owned data infrastructure — the personal event bus, consumer entitlements as dead capital, and the n=1 cost-of-living index. Series II turns to systems gaps: behavior under scarcity, storage that remembers, the scheduling of human attention, and one machine across many devices. Each paper verifies its gap against the existing landscape before proposing anything.

P-004

Degradation Contracts: Specifying and Enforcing How Software Behaves Under Pressure

Behavior under abundance is specified, tested, and monitored; behavior under resource pressure is accidental and unaudited. A formal model — fidelity ladders, shedding orders, recovery hysteresis, floor invariants — plus a pressure-broker runtime and a degradation ledger. The missing discipline for the era when quality is a runtime variable.

P-005

Provenance-Native Storage: The File System as a Causal Ledger

PASS proved automatic file provenance in 2006; nothing shipped. The barriers have expired — eBPF/ES/ETW capture, content-addressed ledgers, on-device models, C2PA's market education. A causal event ledger per volume, an application transform contract, and the query algebra for the questions users already ask: where did this come from, what breaks if I delete it, reproduce this.

P-006

The Attention Scheduler: Interruption Economics as an Operating System Problem

OSes schedule CPUs with fifty years of fairness theory; human attention gets a DND toggle and an adversarial notification economy. The specification of a real scheduler for humans: interruption-cost models, admission control, breakpoint dispatch, per-app attention budgets with honesty pricing, urgent-class latency bounds, and an attention ledger — before closed platforms specify it badly.

P-007

The Intermittent Compute Fabric: One Machine Across Many Devices

The median user owns five-plus devices that behave as islands joined by cloud meters. The offloading research line died in 2012 for reasons the substrate has erased: mesh reachability, WASM portability, device identity, and the first workload that wants it — distributed local AI. The scheduler, capability-delegation protocol, and partition-tolerant task semantics that make a device set programmable as one machine.

About

p-rick is an independent research program, not a product. Its subject is missing software: categories where a real problem meets a large audience and no incumbent — verified against the landscape before anything is proposed, not asserted after. Every paper states its gap as a falsifiable claim, grades the evidence honestly (strong / partial / weak), and confronts the strongest objections to its own thesis.

The program runs research-first: papers before products, always. Work is tracked in agents.md — an automatic session ledger recording what was done, when, and by which agent, so nobody has to remember or ask how long anything took.

Series I (user-owned data and the economics of inattention) began inside srivtx/pocketveto and moved here when the program outgrew its host. Series II (systems gaps) was researched, written, and published from this repository. Everything is open: sources, PDFs, and the site.
